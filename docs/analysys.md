# Анализ предметной области: GrainCounter

## 1. Описание предметной области
GrainCounter - информационная система для автоматизации учета заказов в работе кофейни: ведение клиентов и меню, оформление и сопровождение заказов по статусам, расчёт выручки за месяц и разграничение доступа сотрудников. Ключевые особенности — фиксация цены позиции на момент продажи (чтобы изменение прайса не искажало историческую выручку) и учёт себестоимости для аналитики прибыли.

## 2. Сущности и атрибуты
| Сущность | Атрибуты | Описание |
|----------|----------|----------|
| customers | id (PK), full_name, phone, email (UNIQUE) | Клиент кофейни |
| menu_items | id (PK), name, category, price, cost_price | Позиция меню (напиток, десерт) |
| orders | id (PK), customer_id (FK), order_date, status | Заказ клиента |
| order_items | 	id (PK), order_id (FK), item_id (FK), quantity, price_at_sale, discount_applied | Позиция заказа |
| monthly_revenue | id (PK), year, month, revenue, orders_count, prev_revenue, growth_percent, calculated_at | выручка за месяц |
| users | id (PK), employee_id (FK, NULL), username (UNIQUE), password_hash, role, is_active, last_login_at, created_at | Учётная запись сотрудника системы |


## 3. Бизнес-процессы

## 3.1. Оформление заказа
Клиент выбирает позиции из меню, менеджер/бариста создаёт заказ со статусом «Новый». В order_items фиксируются quantity, price_at_sale (цена на момент продажи) и discount_applied (скидка по позиции), чтобы последующее изменение прайса в menu_items не искажало прошлую выручку.


## 3.2. Ведение заказа по статусам
Заказ проходит жизненный цикл: «Новый» → «Готов» → «Выдан». Переходы фиксируются в orders.status; только выданные заказы учитываются в выручке.


## 3.3. Управление меню
Администратор/менеджер добавляет и редактирует позиции: название, категорию («Кофе», «Десерты»), цену продажи и себестоимость (cost_price) — последняя нужна для аналитики прибыли по позициям и заказам.


## 3.4. Расчёт выручки за месяц
Система агрегирует данные из orders + order_items по месяцам и сохраняет в monthly_revenue: суммарная выручка (revenue), количество выданных заказов (orders_count), выручка предыдущего месяца (prev_revenue), рост в % (growth_percent) и время расчёта (calculated_at).

## 3.5. Аутентификация и разграничение доступа

Сотрудник входит по username + паролю; пароль хранится только в виде хэша (password_hash, bcrypt/argon2). Система проверяет is_active (блокировка аккаунта), фиксирует last_login_at, доступ к функциям определяется ролью. Аккаунт может быть без привязки к сотруднику (владелец) — тогда employee_id = NULL.

## 4. Роли пользователей

Админи — управляет меню, пользователями, видит всю аналитику выручки и прибыли
Бариста — ведёт заказы по статусам («Новый» → «Готов» → «Выдан»), оформляет продажи, работает с клиентами и меню
